# Feature Specification: README проекта для GitHub

**Feature Branch**: `004-project-readme`

**Created**: 2026-08-26

**Status**: Draft

**Input**: User description: "Нужно в корень проекта добавить файл README.md для отображения информации о проекте на странице GitHub. Тут важно соблюсти всю пунктуацию, чтобы отображение текста было правильным, с соответствующими разделителями и обозначением перечислений, а также важно вставить именно такую ссылку на скрин готовой страницы. Сам скрин разместил в корне проекта. Вот заготовленный текст файла: [заготовка с описанием проекта, технологиями, функциональностью, командой запуска и контекстом тестового задания]"

## User Scenarios & Testing _(mandatory)_

### User Story 1 - Просмотр README на странице репозитория GitHub (Priority: P1)

Посетитель страницы репозитория на GitHub (рекрутер, технический интервьюер, коллега) открывает главную страницу репозитория и видит корректно отрендеренный `README.md`: название проекта, краткое описание назначения, скриншот готовой страницы, список использованных технологий, перечень функциональности, инструкцию по запуску проекта и пояснение контекста (тестовое задание на позицию fullstack-разработчика).

**Why this priority**: Это единственная и самодостаточная функциональность фичи. Без корректно оформленного README на странице репозитория GitHub посетитель не получает никакой структурированной информации о проекте — только список файлов.

**Independent Test**: Открыть страницу репозитория `https://github.com/R2u1s/my-page` и убедиться, что под списком файлов отображается отрендеренный README с чётко разделёнными заголовками, маркированными списками и скриншотом — без слипшегося текста и без искажений разметки.

**Acceptance Scenarios**:

1. **Given** пользователь открывает страницу репозитория на GitHub, **When** GitHub рендерит `README.md`, **Then** заголовок, вводный абзац, скриншот, разделы «Технологии», «Функциональность», раздел про запуск проекта и заключительный абзац про контекст задания отображаются как отдельные визуально разделённые блоки, а не как один слитный текст.
2. **Given** README отрендерен на GitHub, **When** пользователь просматривает разделы «Технологии» и «Функциональность», **Then** каждый пункт перечисления отображается как отдельный элемент маркированного списка, а не как текст с символами `*` внутри абзаца.
3. **Given** README отрендерен на GitHub, **When** пользователь доходит до места скриншота, **Then** по ссылке `https://github.com/R2u1s/my-page/blob/main/screen.jpg` отображается изображение готовой страницы проекта.
4. **Given** README отрендерен на GitHub, **When** пользователь читает раздел про запуск, **Then** команда `docker compose up -d` отображается отдельно от окружающего текста (не слитно со словом перед ней).

---

### Edge Cases

- Что если файл `screen.jpg` ещё не запушен в удалённый репозиторий на момент просмотра README — ссылка на изображение будет "битой" до его публикации; размещение самого файла изображения в репозитории — ответственность пользователя и вне рамок этой фичи (пользователь подтвердил, что уже разместил файл в корне проекта).
- Что если исходный текст-заготовка не содержит явных переносов строк между смысловыми блоками (заголовками разных уровней и списками) — необходимо восстановить корректную Markdown-структуру (пустые строки между блоками, отдельные строки для каждого пункта списка) по смыслу заголовков (`#`, `##`, `###`, `####`) и маркеров перечисления (`*`), сохранив исходные формулировки и порядок контента без искажений.
- Что если два раздела подряд оформлены заголовком одного уровня (`####` — «Запуск» и «Контекст выполнения задания») — они должны остаться двумя визуально различимыми разделами с собственными заголовками, а не слиться в один блок текста.

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: В корне репозитория должен появиться файл `README.md`.
- **FR-002**: README MUST содержать главный заголовок первого уровня (`#`) с названием проекта — «Визитка».
- **FR-003**: README MUST содержать вводный абзац, описывающий назначение страницы: личная страница-визитка, содержащая контакты, описание опыта и навыков.
- **FR-004**: README MUST содержать встроенное изображение скриншота готовой страницы по ссылке `https://github.com/R2u1s/my-page/blob/main/screen.jpg` — эта ссылка сохраняется буквально, без изменений (без замены на `raw.githubusercontent.com`, без добавления `?raw=true` или иных модификаций), в точности как указал пользователь.
- **FR-005**: README MUST содержать раздел «Технологии» (заголовок второго уровня, `##`) с маркированным списком, перечисляющим используемый стек по группам в том же составе и порядке, что в исходном тексте: (1) TypeScript, React, Material UI, TanStack React Query; (2) Nest.js, PostgreSQL, GraphQL; (3) Jest, Vitest; (4) Docker; (5) Claude Code — каждая группа отдельным пунктом списка.
- **FR-006**: README MUST содержать раздел «Функциональность» (заголовок третьего уровня, `###`) с маркированным списком из трёх пунктов: отображение информации обо мне, контактов и навыков; ссылки на готовые публичные проекты; счётчик посещений.
- **FR-007**: README MUST содержать раздел с инструкцией запуска проекта (заголовок четвёртого уровня, `####`), явно указывающий команду `docker compose up -d` как способ запуска.
- **FR-008**: README MUST содержать заключительный раздел (заголовок четвёртого уровня, `####`), поясняющий контекст создания проекта: выполнен в рамках тестового задания на позицию fullstack-разработчика с применением Claude Code.
- **FR-009**: Вся Markdown-разметка (уровни заголовков, переносы строк между блоками, оформление маркированных списков и пунктуация внутри предложений) MUST быть восстановлена и исправлена относительно «слипшегося» исходного текста-заготовки так, чтобы GitHub отрендерил документ читаемо и структурированно, при этом MUST быть сохранены исходный смысл, порядок и формулировки контента — без добавления нового смысла и без удаления присутствующего в заготовке.
- **FR-010**: Текст README MUST оставаться на русском языке, как в предоставленной заготовке.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: Посетитель страницы репозитория на GitHub понимает назначение проекта, используемые технологии и способ его запуска за одно прочтение отрендеренной страницы, без необходимости открывать исходный код.
- **SC-002**: 100% содержательных пунктов исходного текста-заготовки (описание, технологии, функциональность, команда запуска, контекст задания) присутствуют в отрендеренном README без потерь и без искажения смысла.
- **SC-003**: Markdown-разметка README отображается на странице репозитория GitHub без ошибок рендера — заголовки, маркированные списки и изображение отображаются каждый как собственный визуально обособленный блок.
- **SC-004**: Ссылка на скриншот в отрендеренном README в точности совпадает со строкой `https://github.com/R2u1s/my-page/blob/main/screen.jpg`, указанной пользователем, без каких-либо модификаций.

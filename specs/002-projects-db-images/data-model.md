# Phase 1 Data Model: Проекты из постоянного хранилища данных с изображениями

Эта фича вводит первую реальную доменную таблицу в БД проекта — до неё `Project` описывался в
`specs/001-personal-landing-page/data-model.md` как "статичный frontend-конфиг, а не таблица базы данных".
Данная спецификация сознательно заменяет это решение: `Project` теперь хранится в PostgreSQL через Prisma и
читается через GraphQL. Раздел ниже — новая версия модели `Project`, действующая начиная с этой фичи.

## Project (БД-таблица + GraphQL-тип + frontend-тип, все три синхронизированы вручную)

Карточка портфолио в блоке проектов.

| Поле            | Тип (Prisma)                  | Тип (GraphQL) | Обязательность | Описание                                                                                                                                                                         |
| --------------- | ----------------------------- | ------------- | -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `id`            | `String @id @default(cuid())` | `ID!`         | обязательное   | Уникальный идентификатор карточки. Для существующих записей — стабильные читаемые значения (`"himnavigator"`, `"placeholder"`), заданные явно сид-скриптом, а не сгенерированные |
| `title`         | `String`                      | `String!`     | обязательное   | Название проекта ("Навигатор Химии")                                                                                                                                             |
| `description`   | `String`                      | `String!`     | обязательное   | Описание проекта; для карточки-заглушки — пустая строка                                                                                                                          |
| `url`           | `String?`                     | `String`      | опциональное   | Внешняя ссылка; отсутствует (`null`) для карточки-заглушки                                                                                                                       |
| `imageUrl`      | `String?`                     | `String`      | опциональное   | Ссылка на изображение-превью во внешнем файловом хранилище; отсутствует, если для проекта нет изображения                                                                        |
| `isPlaceholder` | `Boolean @default(false)`     | `Boolean!`    | обязательное   | `true` для карточки "Список будет дополняться"                                                                                                                                   |
| `sortOrder`     | `Int`                         | `Int!`        | обязательное   | Порядок отображения в списке (по возрастанию); управляется данными, не кодом                                                                                                     |
| `createdAt`     | `DateTime @default(now())`    | —             | обязательное   | Служебное поле аудита, GraphQL не отдаёт                                                                                                                                         |
| `updatedAt`     | `DateTime @updatedAt`         | —             | обязательное   | Служебное поле аудита, GraphQL не отдаёт                                                                                                                                         |

**Validation rules**:

- Если `isPlaceholder === true`, то `url` и `imageUrl` равны `null`, карточка не кликабельна (соответствует
  FR-003, FR-007, наследуется из `001-personal-landing-page`).
- Если `isPlaceholder === false`, `url` ДОЛЖЕН быть непустой валидной внешней ссылкой, открываемой с
  `target="_blank"` и `rel="noopener noreferrer"` (FR-008, наследуется из `001-personal-landing-page`, FR-007).
- `imageUrl`, если указан, — синтаксически валидный URL, ведущий на изображение во внешнем хранилище файлов
  (не локальный статический ассет фронтенда; см. FR-002).
- `sortOrder` уникален в пределах активного списка на уровне соглашения (не enforced на уровне схемы БД) —
  дублирующиеся значения допустимы, но не гарантируют стабильный порядок между одинаковыми значениями.

**State / список**:

- Список проектов — упорядоченная по `sortOrder` (по возрастанию) выборка всех записей таблицы `Project`
  (GraphQL query `projects` возвращает уже отсортированный список — см. `contracts/graphql-projects.md`).
- Минимум одна запись с `isPlaceholder === false` и одна с `isPlaceholder === true` на момент переноса данных
  (FR-007) — это ограничение соглашения о данных на момент миграции, не enforced на уровне схемы.
- Добавление нового проекта — вставка новой строки в таблицу `Project` (администратором/разработчиком,
  напрямую в БД или через Prisma Studio/скрипт), без изменения кода фронтенда или бэкенда (FR-005).

**Relationships**: сущность независима от остальных сущностей лендинга (`Profile`, `Skill`, `VisitCounter` из
`001-personal-landing-page`) — миграция затрагивает только `Project` (см. Assumptions в `spec.md`).

## Миграция данных (перенос двух существующих записей)

Выполняется Prisma-сид-скриптом (`apps/backend/prisma/seed.ts`), не вручную через SQL — соответствует принципу
VII (никаких изменений структуры/данных в обход Prisma). Использует `prisma.project.upsert` по `id`, чтобы
повторный запуск сида был идемпотентным:

| `id`           | `title`                    | `url`                | `imageUrl`                                                     | `isPlaceholder` | `sortOrder` |
| -------------- | -------------------------- | -------------------- | -------------------------------------------------------------- | --------------- | ----------- |
| `himnavigator` | "Навигатор Химии"          | `https://chmtch.ru/` | `http://localhost:9000/project-images/chmtch-screen.png` (dev) | `false`         | `1`         |
| `placeholder`  | "Список будет дополняться" | `null`               | `null`                                                         | `true`          | `2`         |

Значение `imageUrl` для продакшена не фиксируется в этой спецификации (провайдер объектного хранилища для
эксплуатации выбирается отдельно, см. Assumptions в `spec.md`) — при переносе на прод-провайдер значение
достаточно обновить записью в БД, без изменений кода.

# Feature Specification: Проекты из постоянного хранилища данных с изображениями

**Feature Branch**: `002-projects-db-images`

**Created**: 2026-08-25

**Status**: Draft

**Input**: User description: "Блок \"Проекты\" на лендинге должен брать список проектов из базы данных вместо захардкоженного конфига. В сущность проекта добавляется новое поле image (ссылка/URL на картинку). Картинки хранятся в S3-совместимом объектном хранилище: локально для разработки поднимаем MinIO в docker-compose, решение по продовому провайдеру откладывается на потом и должно конфигурироваться через переменные окружения. Загрузка картинок в бакет на этом этапе выполняется вручную, никакого backend API для загрузки файлов и никакой админки/аутентификации не требуется. Данные читаются через GraphQL-запрос, доступ к БД — через Prisma с обязательной миграцией. Нужно перенести уже существующие два проекта (\"Навигатор Химии\" и заглушку \"Список будет дополняться\") из захардкоженного конфига в БД через seed, включая ссылку на картинку для \"Навигатор Химии\". Frontend должен получать список проектов через TanStack Query, карточка проекта должна отображать картинку, если она есть, и корректно работать без неё. Список проектов должен поддерживать порядок отображения и оставаться расширяемым."

## User Scenarios & Testing _(mandatory)_

### User Story 1 - Посетитель видит проект с иллюстрацией (Priority: P1)

Посетитель, листающий блок "Проекты", хочет увидеть визуальное превью каждого проекта (скриншот, лого), чтобы быстрее оценить, о чём проект, не читая длинное текстовое описание.

**Why this priority**: изображение — самый заметный элемент карточки портфолио, повышает вовлечённость и доверие к перечисленным работам; сейчас карточки полностью текстовые.

**Independent Test**: открыть блок проектов — у карточки "Навигатор Химии" отображается изображение-превью проекта; у карточки-заглушки изображения нет, и это не ломает вёрстку.

**Acceptance Scenarios**:

1. **Given** посетитель находится на лендинге, **When** он долистал до блока проектов, **Then** карточка "Навигатор Химии" отображает изображение проекта вместе с названием и описанием.
2. **Given** у проекта не указано изображение (например, у карточки-заглушки), **When** карточка отображается, **Then** карточка выглядит корректно и завершённо, без пустых рамок, битых иконок или обрезанного макета на месте изображения.

---

### User Story 2 - Обновление списка проектов без изменения кода (Priority: P1)

Владелец сайта хочет добавить новый проект или изменить существующий (название, описание, ссылку, изображение, порядок), не привлекая разработку и не выпуская новую версию фронтенда.

**Why this priority**: это основная мотивация переноса данных из кода в хранилище — раньше любое изменение списка проектов требовало правки исходного кода и повторной публикации сайта.

**Independent Test**: изменить данные проекта в хранилище данных, не трогая код фронтенда, — после обновления страницы посетитель видит изменения.

**Acceptance Scenarios**:

1. **Given** в хранилище данных изменено название, описание, ссылка или изображение проекта, **When** посетитель открывает (или обновляет) лендинг, **Then** он видит обновлённые данные без пересборки и повторной публикации фронтенда.
2. **Given** в хранилище данных добавлена новая запись проекта, **When** посетитель открывает блок проектов, **Then** новая карточка появляется в списке на предусмотренном для неё месте.

---

### User Story 3 - Сохранение текущего содержимого при переносе (Priority: P2)

Посетитель, уже знакомый со страницей, должен продолжать видеть тот же список проектов ("Навигатор Химии" и заглушку "Список будет дополняться") после переноса данных в новое хранилище — без потери или искажения контента.

**Why this priority**: гарантирует отсутствие видимой регрессии для существующих посетителей и ссылок на сайт; менее приоритетно, чем сама возможность отображать изображения и обновлять данные без кода, но обязательно для безопасного перехода.

**Independent Test**: сравнить список и порядок карточек проектов до и после переноса — состав и порядок совпадают, у "Навигатор Химии" дополнительно появляется изображение.

**Acceptance Scenarios**:

1. **Given** перенос данных выполнен, **When** посетитель открывает блок проектов, **Then** он видит те же два проекта в том же порядке, что и раньше, при этом у "Навигатор Химии" теперь также отображается изображение.
2. **Given** перенос данных выполнен, **When** посетитель нажимает на ссылку карточки "Навигатор Химии", **Then** переход по ссылке `https://chmtch.ru/` по-прежнему открывается в новой вкладке, как и раньше.

---

### Edge Cases

- Что происходит, если изображение проекта недоступно (например, ссылка на файл стала нерабочей): карточка не должна показывать битую иконку изображения или ломать раскладку — место под изображение должно корректно обрабатываться на уровне интерфейса.
- Что происходит, если список проектов в хранилище данных временно пуст: блок проектов должен отображаться корректно, без ошибок рендера и без пустых/битых карточек.
- Что происходит, если источник данных временно недоступен при загрузке страницы: посетитель должен увидеть понятное, не сломанное состояние блока проектов (не бесконечно пустая область и не ошибка на весь экран).
- Что происходит с порядком новых проектов, если для них явно не указано место в списке: они должны появляться в списке предсказуемым образом (не в случайном порядке при каждой загрузке страницы).

## Requirements _(mandatory)_

### Functional Requirements

- **FR-001**: Система ДОЛЖНА получать и отображать список проектов из постоянного хранилища данных, а не из значений, зашитых в код интерфейса.
- **FR-002**: Каждая карточка проекта ДОЛЖНА поддерживать необязательное изображение-превью; если для проекта указано изображение — оно отображается в карточке.
- **FR-003**: Если изображение для проекта не указано (в том числе для карточки-заглушки), карточка ДОЛЖНА отображаться корректно, без пустых рамок или битых иконок на месте изображения.
- **FR-004**: Изменение данных существующего проекта (название, описание, ссылка, изображение) в хранилище данных ДОЛЖНО становиться видимым посетителям без изменения кода фронтенда и без его повторной публикации.
- **FR-005**: Добавление нового проекта в хранилище данных ДОЛЖНО становиться видимым посетителям в блоке проектов без изменения кода.
- **FR-006**: Список проектов ДОЛЖЕН отображаться в явно определённом порядке, управляемом данными, а не порядком, зашитым в код.
- **FR-007**: После переноса данных блок проектов ДОЛЖЕН по-прежнему содержать существующие записи — карточку "Навигатор Химии" (с прежним описанием, ссылкой `https://chmtch.ru/` и присвоенным ей изображением) и карточку-заглушку "Список будет дополняться" — в прежнем порядке.
- **FR-008**: Внешние ссылки проектов, как и раньше, ДОЛЖНЫ открываться в новой вкладке браузера, оставляя лендинг открытым в исходной.
- **FR-009**: Добавление, изменение и удаление изображений и данных проектов на этом этапе выполняется напрямую в хранилище данных и файлов лицом, администрирующим сайт; отдельный встроенный в сайт интерфейс управления или загрузки файлов НЕ ТРЕБУЕТСЯ и находится вне объёма этой фичи.
- **FR-010**: Блок проектов ДОЛЖЕН корректно отображаться (без ошибок рендера и сломанной страницы), если источник данных временно недоступен или список проектов пуст.

### Key Entities _(include if feature involves data)_

- **Проект (Project)**: представленная работа в портфолио — уникальный идентификатор, название, описание, внешняя ссылка (отсутствует у карточки-заглушки), необязательное изображение-превью, признак "карточка-заглушка", порядок отображения в списке. Хранится в постоянном хранилище данных, а не в коде интерфейса; список упорядочен и допускает добавление новых записей без изменения кода.

## Success Criteria _(mandatory)_

### Measurable Outcomes

- **SC-001**: Обновление данных существующего проекта (название, описание, ссылка, изображение) или добавление нового проекта становится видимым посетителям в течение обычного времени загрузки страницы, без выпуска новой версии фронтенда.
- **SC-002**: 100% карточек проектов с указанным изображением отображают это изображение корректно, без искажения раскладки, на экранах desktop и mobile.
- **SC-003**: 100% карточек без изображения (включая карточку-заглушку) отображаются без визуальных дефектов — пустых рамок или битых иконок на месте изображения.
- **SC-004**: После переноса данных список и порядок проектов, видимых посетителю, на 100% совпадает с содержимым, отображавшимся до переноса, за исключением добавленного изображения у "Навигатор Химии".
- **SC-005**: Блок проектов остаётся работоспособным (не показывает ошибку на весь экран и не оставляет пустой сломанный блок) при временной недоступности источника данных или пустом списке проектов.

## Assumptions

- Изображения проектов размещаются во внешнем файловом хранилище администратором сайта вручную, вне интерфейса сайта; встроенная в сайт загрузка файлов через UI или API — предмет отдельной будущей фичи, вне объёма текущей.
- Управление данными проектов (добавление, изменение, удаление записей) на этом этапе выполняется напрямую в хранилище данных администратором/разработчиком; отдельная административная панель — вне объёма текущей фичи.
- Аутентификация и разграничение прав доступа не требуются: посетитель не выполняет никаких действий, изменяющих данные (согласуется с Assumptions спецификации `001-personal-landing-page`).
- Конкретный провайдер файлового хранилища для промышленной эксплуатации выбирается отдельно и не фиксируется в этой спецификации; для разработки допустимо использовать любое совместимое с ней решение.
- Изображение проекта "Навигатор Химии", уже подготовленное ранее, переносится в новое хранилище как часть переноса данных без изменения содержания.
- Порядок отображения проектов управляется явным значением, хранящимся вместе с данными проекта; при его отсутствии для новой записи используется порядок добавления.
- Данный перенос затрагивает только сущность "Проект"; остальные блоки лендинга (профиль, навыки, счётчик посещений), описанные в `001-personal-landing-page`, не изменяются.

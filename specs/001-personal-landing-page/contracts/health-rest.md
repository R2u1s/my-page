# Contract: REST `GET /health`

Единственный REST-эндпоинт в системе (исключение из принципа VI конституции — "GraphQL как единственный
API-контракт").

## Request

```
GET /health
```

Без параметров, без тела запроса, без аутентификации.

## Response — 200 OK

```json
{
  "status": "ok"
}
```

| Поле     | Тип    | Описание                                                                              |
| -------- | ------ | ------------------------------------------------------------------------------------- |
| `status` | `"ok"` | Литеральная строка, подтверждающая, что процесс backend запущен и отвечает на запросы |

## Failure modes

Эндпоинт не выполняет проверок внешних зависимостей на этом этапе (см. `research.md`, п.5) — если процесс
backend запущен, всегда отвечает `200 OK`. Недоступность самого процесса (краш, не поднялся) — интерпретируется
инфраструктурой (Docker healthcheck) как таймаут/connection refused, отдельного кода ошибки контракт не
определяет.

## Consumers

- Docker Compose `healthcheck` для сервиса `backend`.
- Ручная проверка при локальной разработке.
- Frontend на этом этапе НЕ обращается к этому эндпоинту (нет соответствующего сценария в спецификации).
